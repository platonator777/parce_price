# Исправление обработки combined_results_20261005_151843.parquet

Актуальный результат после уточнения про ползунки: **24 125 строк**, включая
7 706 вариантов МТС, 98 Letai и 754 Wifire.ru. Каждая позиция ползунка МТС
сохранена отдельно. Выборочная проверка выявила и устранила дополнительные
пропуски HTML-карточек Letai и встроенных тарифов Wifire.ru.
Отчёт: [MANUAL_AUDIT.md](qa-20261005/MANUAL_AUDIT.md).
Ниже сохранена история первой проверки; её 20 127 строк уже не актуальны.

## Что ломалось

1. В файле 2 965 строк со столбцами `provider`, `region`, `city`, `url`,
   `timestamp`, `content`, `status`. Загрузчик не поддерживал `content` и
   завершался с `input must contain html, html_content, or response_json`.
2. JSON-ветка МТС использовала `**first(...)`, хотя `first` возвращает одно
   значение, а не словарь полей. Новый API использует `title`, `totalPrice`,
   `internetTariff` и `productFeatureGroups`, а не прежние плоские поля.
3. JSON-ветка Билайна ссылалась на неопределённую переменную `fact`.
   Кроме того, прежний `json_items` не находил тарифы в
   `blocks[alias=catalog].data.tariffs`: мог получиться пустой результат без ошибки.
4. Старый запуск с `--provider mts` на смешанном файле заменял имя оператора
   у всех строк. Теперь источник с явным `provider` фильтруется.
5. Ранее установленная копия Python-пакета могла скрывать исправления в `src`.
   Теперь `run_pipeline.py` явно загружает локальный `src` из своей папки.

## Что изменено

- Чтение `content`, определение JSON/HTML по каждой строке, сохранение `status`.
- Запуск смешанного файла без `--provider`, выбор готового адаптера по строке,
  алиасы `wifire_ru → wifireru`, `ooofirmaintersvyaz → intersvyaz`.
- Извлечение реальных вложенных полей API МТС и каталога Билайна.
  Исходный объект тарифа сохраняется в `raw_offer`.
- Проверка соответствия выходных полей исходным API-полям, включая перевод
  Гбит/с в Мбит/с. Старая проверка HTML сохранена.
- Ошибки сбора и пустой payload записываются в `errors.jsonl`, обработка
  остальных строк продолжается. Успешные страницы без тарифов учитываются
  отдельно как `records_empty`, со статистикой по каждому оператору.
- Проверка чисел HTML сканирует исходную страницу один раз на запись,
  вместо повторного сканирования для каждого числового поля каждого тарифа.
- Добавлен вывод прогресса каждые 100 записей.

## Что уже отсутствует в исходных данных

В исходном файле 301 строка с `status=error` и пустым `content`:
236 у Билайна и 65 у `wifire_ru`. Тарифы для них нельзя восстановить из этого
parquet: коллеге нужно повторить сбор этих адресов. Их URL есть в `errors.jsonl`.

Также `evo73.ru` помечен как `success`, но содержит HTML ошибки 404.
У `rightside.ru` в сохранённом HTML нет каталога с ценами тарифов.
Пустой результат таких страниц не означает отсутствие тарифов у оператора.
В МТС есть три ответа `[]`.

## Запуск

Из корня этого рабочего проекта, где находится исходный parquet:

```powershell
.venv/Scripts/python.exe final/run_pipeline.py --input ../combined_results_20261005_151843.parquet
```

Относительный `--input` разрешается от папки `final`, поэтому здесь нужен `../`.
В распакованной поставке инструкция установки и варианты расположения файла
описаны в `README.md`. Ollama для этого запуска не нужен.

Для одного оператора добавьте `--provider mts` или `--provider beeline`.
Полный прогон с исходными ошибками возвращает ненулевой код завершения,
но сохраняет CSV успешных записей.
